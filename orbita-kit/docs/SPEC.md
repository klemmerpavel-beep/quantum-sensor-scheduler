# Спецификация прототипа «Орбита · ЯМГ-ИИМ · Этап 1»

Этап 4 блока II. Спецификация согласована со сводом решений `docs/DECISIONS.md` (Р-01…Р-49). Ссылка вида «[Р-19]» указывает на решение, из которого следует правило; при расхождении приоритет у DECISIONS.md.
Нормативные слова: **должен** — обязательно для приёмки; **может** — допустимо.

Каждая HTML-страница самодостаточна: HTML + CSS + JS в одном файле, данные встроены константой `SEED`. Она открывается двойным щелчком (`file://`) и как опубликованная страница. Внешние ресурсы — только Google Fonts (Inter, IBM Plex Mono). Без них страница работает на системных гарнитурах [Р-40, Р-42].

Исходники: `src/` (стили, модуль расчёта, отрисовка режимов) и `tools/build.py` (склейка в три файла). Сборка нужна только для сопровождения; результат хранится в репозитории готовым.

## 2. Модель состояния страницы

Три слоя. Производные признаки не хранятся, а вычисляются заново при любом изменении первых двух слоёв.

### 2.1. Исходные данные (неизменяемы)
- `SEED` — дословная копия `data/seed_ymg_stage1.json` [Р-01].
- `CONFIG` — константы из решений:
  - `CHAIN = ["2.1.7","2.1.6","2.2.2","2.2.5.1","2.2.4.1","2.2.5.2","2.2.5.3","2.2.5.5"]`, питающая ветвь `{from:"2.1.9", to:"2.2.5.3"}` [Р-23, Р-24];
  - `HOLIDAYS` — 04.11.2026, 31.12.2026, 01–08.01.2027 [Р-04];
  - `ORGS` — `elektropribor → «Электроприбор»`, `fti → «ФТИ им. Иоффе»`, `ihs → «ИХС им. Гребенщикова»` [Р-28];
  - `LINKS` — 6 связей уровня EXTRACTED для боковой панели (DATA_MAP §8) [Р-46];
  - `VARIANT` — `panel | registry | path` [Р-45].

### 2.2. Правки пользователя
`EDITS[num] = { status?, closeDoc?: {name, letter, date}, comment? }`.
- Правки живут в памяти страницы.
- Они зеркалируются в `localStorage` под ключом `orbita.ymg-iim.s1.edits.v1`. Каждое обращение к `localStorage` — в `try/catch`; при ошибке страница работает без сохранения и один раз показывает строку «Отметки хранятся только до перезагрузки страницы» [ограничение постановки].
- Правка возможна только в полном представлении без `?view=exec` и `?org` [Р-27].
- Кнопка «Сбросить отметки» возвращает исходные данные.

### 2.3. Состояние интерфейса
- Текущий режим и открытая позиция (боковая панель).
- Фильтры «Исполнитель» и «Раздел», строка поиска.
- Свёрнутые разделы в «Ганте», срез «Ганта»: `all | overdue | chain`.
- Тема.
- Состояние интерфейса, кроме темы, в `localStorage` не пишется.

## 4. Производные признаки

Даты сравниваются как календарные дни без времени. «Сегодня» = `T`.

### 4.1. Рабочие дни
`Δ(a, b)` — число рабочих дней в интервале (a; b] со знаком; рабочий день — пн–пт вне `HOLIDAYS`. Контроль: Δ(15.09, 30.09) = 11, Δ(27.11, 30.11) = 1 [Р-47].

### 4.2. Отображаемый статус [Р-15]
Первое сработавшее правило:
1. `EDITS[num].status`.
2. `SEED.status`, если `status_mark` ≠ null (17 позиций).
3. Подпозиция группы, `due < T`, у группы хранимый статус → статус группы, пометка `inherited = <номер группы>` [Р-12, Р-16].
4. `due < T` → «Нет отметки» [Р-13].
5. Иначе «Не начато».

Для групповой позиции без хранимого статуса пп. 3–5 заменяются расчётом по отображаемым статусам подпозиций, пометка `derived` [Р-14]:
- все «Закрыто» → «Закрыто»;
- есть «Закрыто» или любой статус, кроме «Не начато» и «Нет отметки» → «В работе»;
- есть «Нет отметки» → «Нет отметки»;
- иначе «Не начато».

Разделы статуса не имеют.

### 4.3. Признаки срока
- **Просрочено** [Р-19]: статус ≠ «Закрыто» ∧ `due < T`; `overdueDays = T − due` (календарные).
- **Срок ≤ 7 дней**: статус ≠ «Закрыто» ∧ `0 ≤ due − T ≤ 7`.
- **Контрольная дата прошла** [Р-20]: статус ≠ «Закрыто» ∧ `control_date < T`; число дней — календарных.
- **Без реквизита** [Р-31, Р-32]: статус «Закрыто» ∧ нет `closed_date` в данных и нет `closeDoc` в правке, либо `closeDoc` без наименования документа.
- **Остаток**: «через N дн.» (N > 0), «сегодня» (N = 0), «просрочено N дн.» (N < 0).

### 4.4. Горизонты «Фокуса»
Для незакрытых позиций (работы и группы; разделы — нет), по `d = due − T`:
- «Просрочено» (d < 0);
- «Ближайшие 14 дней» (0…14);
- «30 дней» (15…30);
- «60 дней» (31…60);
- «Позднее» (> 60), свёрнуто.

Отдельно «Закрыто», свёрнуто, включает позицию вне План-графика [Р-34]. Горизонты не пересекаются.

### 4.5. База KPI [Р-17, Р-21, Р-44]
`BASE` — позиции, у которых родитель — раздел (39, включая 5 групп), плюс подпозиции групп с непустым `due_to_customer` (8). Итого 47.

Показатели «Сводки»:
- **Закрыто**: K из 47, доля в %, «из них без реквизита: N».
- **План на дату**: срок наступил (`due < T`) — N1; из них закрыто — N2, просрочено — N3; закрыто досрочно (`due ≥ T`) — N4.
- **Просрочено**: N3; вторая строка — «контрольная дата прошла: N5».
- **В работе**: статусы «В работе», «Подготовка материалов», «Ожидаем документ», «На согласовании» в BASE.
- **До демонстрации ЛО**: Δ(T, 30.11.2026) раб. дн. и календарные дни; после даты — «демонстрация прошла».
- **До окончания этапа**: календарные дни до 30.12.2026.

Контроль на 28.09.2026:

| Показатель | Значение |
|---|---|
| Закрыто | 10 из 47 (21 %), без реквизита — 1 |
| План на дату | 10 / 8 / 2 / 2 |
| Просрочено | 2 (контрольная дата прошла — 2) |
| До демонстрации ЛО | 44 раб. дн. (63 дн.) |
| До окончания этапа | 93 дн. |

### 4.6. Прогресс
- Группа: «закрыто / всего подпозиций» по отображаемому статусу [Р-18].
- Раздел (1, 2.1, 2.2, 3): закрытые / позиции раздела из BASE, число просроченных.

### 4.7. Окно критической цепочки [Р-47]
Для звеньев `CHAIN` и питающей ветви:
- `P = Δ(due_i, due_{i+1})`.
- `F_i = closeDate_i`, если звено закрыто (дата правки или `closed_date`; при отсутствии — `due_i`); иначе `max(due_i, T, F_{i−1} ⊕ min(P_{i−1}, 0))`, где ⊕ — сдвиг на рабочие дни. Прогноз помечается «не ранее».
- `R = Δ(F_i, due_{i+1})`, `E = P − R`.

Состояния окна:

| Состояние | Условие |
|---|---|
| `done` | оба звена закрыты |
| `breach` | R < min(P, 0) |
| `eroding` | E > 0 |
| `overlap` | E = 0 ∧ P < 0 |
| `thin` | E = 0 ∧ 0 ≤ P ≤ 1 |
| `ok` | иначе |

- Дата срыва для `eroding` — первый рабочий день после `due_{i+1}` (если звено `i` к ней не закрыто).
- Состояние цепочки — худшее: breach > eroding > прочие.
- Контроль на 28.09: окно 2.1.7 → 2.1.6 = `eroding`, «осталось 2 из 11 раб. дн., срыв с 01.10.2026»; окна 2.2.2 → 2.2.5.1 и 2.2.5.1 → 2.2.4.1 — `overlap`; цепочка — `eroding`.

### 4.8. «Топ-5 рисков» [Р-26, Д-2]
Отбираются незакрытые позиции в порядке категорий:
1. Звенья цепочки и питающей ветви, просроченные.
2. Звенья цепочки со сроком ≤ 7 дней.
3. Прочие просроченные из BASE.
4. Прочие из BASE с прошедшей контрольной датой.
5. Прочие из BASE со сроком ≤ 7 дней.

Порядок внутри категории:
- по дням просрочки (убывание);
- для категорий «≤ 7 дней» — по остатку (возрастание);
- при равенстве — по порядку позиций в План-графике.

Позиция входит один раз, всего до пяти. Контроль на 28.09: 2.1.7, 2.1.6, 2.1.9, 2.1.5, 1.4.

## 5. Правило «Закрыто» с выдаваемым документом [Р-31]

Смена статуса в боковой панели: переключатель статусов (7 значений) — первое нажатие.

Для «Закрыто» раскрывается форма реквизита:
- наименование документа, по умолчанию `output_doc`;
- № письма;
- дата, по умолчанию `T`.

Кнопка «Закрыть позицию» — второе нажатие. Путь с реквизитом по умолчанию укладывается в два нажатия.

Если наименование документа очищено:
- кнопка меняется на «Закрыть без реквизита»;
- появляется предупреждение «Позиция будет закрыта без реквизита выдаваемого документа»;
- после подтверждения позиция получает пометку «без реквизита».

Любая смена статуса мгновенно пересчитывает все производные признаки и все режимы [BRIEF 10.3].

## 6. Повестка оперативки [Р-33, Р-35, Д-1]

Действие «Повестка оперативки» в «Фокусе». База — BASE (обязательства перед Заказчиком). Просроченные подпозиции без срока Заказчику упоминаются в строке своей группы.

Разделы текста:
1. **Просрочено** — позиции BASE с признаком «Просрочено».
2. **Контрольная дата прошла** — не вошедшие в п. 1.
3. **Срок в ближайшие 14 дней** — не вошедшие в пп. 1–2.

Формат строки: `Наименование — комментарий (п. N)`.
- Комментарий = `comment` пользователя, иначе `status_mark`, иначе строка без тире.
- Для группы с просроченными подпозициями к комментарию добавляется «; просрочены подпозиции 2.1.1.2, 2.1.1.3».

Шапка текста: «Повестка оперативки по этапу 1 ОКР «ЯМГ-ИИМ» на ДД.ММ.ГГГГ». Текст показывается в окне; кнопка «Скопировать» использует Clipboard API, при недоступности — выделяет текст.

## 7. Режимы

| Режим | Состав | Основное действие |
|---|---|---|
| **Сводка** (В1) | ряд KPI; полоса времени этапа (недели, «Сегодня», вехи, недельная плотность сроков BASE); нитка цепочки ЛО с окнами; «Топ-5 рисков»; прогресс разделов | переход в «Гант» по элементу [Р-44] |
| **Сводка «Путь к ЛО»** (В3) | нитка цепочки на всю ширину с карточками звеньев (срок, прогноз, окно); отсчёт до 30.11; «Топ-5»; KPI узкой колонкой; полоса времени | переход к звену |
| **Гант** | таблица: №, наименование, исполнитель, срок, статус, шкала; разделы сворачиваются; срезы «Все / Просроченные / Цепочка ЛО»; в В2 над таблицей полоса из 5 показателей | открыть позицию |
| **Фокус** | горизонты (4.4), «Повестка оперативки» | сформировать повестку |
| **Доска** | 7 колонок словаря статусов, карточки: №, наименование (2 строки), исполнители, срок и остаток | открыть позицию |
| **Вехи** | ось этапа, 8 вех-ромбов, грозди позиций по датам срока (высота — число позиций), список позиций выбранной даты | выбрать дату |
| **Боковая панель** | номер, наименование, статус и смена, даты (срок; срок предоставления Заказчику; контрольная; закрытия; начало — «расчётное»), исполнители, документы, основание, примечание (дословно), отметка «Важного», комментарий, связи, окно цепочки | сменить статус |

Шкала «Ганта»:
- 13.08.2026–01.02.2027, недели;
- полоса от `start` до `due` цвета статуса; при `start_derived` начальный сегмент полупрозрачен;
- просроченная часть от `due` до `T` — штриховка;
- засечка `control_date`;
- ромбы вех;
- линия «Сегодня»;
- цепочка — обводка и номер звена, скобка окна [Р-46].

На ширине ≤ 720 px «Гант» заменяется списком карточек; «Доска» — горизонтальной прокруткой колонок; «Вехи» — вертикальным списком дат [BRIEF 7].
