# Архитектура · CRM «Квантовый сенсор ИИМ ЯМГ (Электроприбор)»

Выпуск 1.4.0 (Р-69…Р-74). Документ описывает устройство прототипа, поток данных, правила расширения и проверки. Предметные правила — в `SPEC.md`, решения — в `DECISIONS.md`, оформление — в `TOKENS.md` и `UX.md`.

## 1. Принципы

| Принцип | Следствие |
|---|---|
| Один файл, без сервера и сборщика на стороне пользователя | Страница открывается двойным щелчком и с любого веб-сервера; во внутреннем контуре — без сети (Р-42, Р-66) |
| Исходные данные неизменяемы | `data/seed_ymg_stage1.json` и `source/*.xlsx` не правятся; контроль по MD5 в `tools/check.sh` |
| Расчёт отделён от отображения | `src/engine.js` — чистые функции без DOM; тестируется в Node.js |
| Правки пользователя — отдельный слой | Отметки хранятся поверх данных и переносимы в общее хранилище без переделки интерфейса (Р-41) |
| Каждое правило прослеживаемо | Код ссылается на решения Р-NN; тесты — на пункты SPEC |

## 2. Поток данных

```
 data/seed_ymg_stage1.json ─┐
 src/config.js ─────────────┤   (краткие наименования, путь к демонстрации, календарь, связи)
 правки пользователя ───────┤   (localStorage, только удобство)
 дата расчёта T ────────────┘   (текущая или ?today)
            │
            ▼
   Engine.build(SEED, CONFIG, edits, T)      src/engine.js — чистая функция
            │
            ▼
   модель M: items, work (66), base (47), kpi, sections,
             chainWindows, chainState, top5, календарь
            │
            ▼
   view*() → HTML-строка                      src/ui/*.js
            │
            ▼
   render(): #app.innerHTML, восстановление фокуса и прокрутки, syncUrl()
            ▲
            │ события (click / input / change / keydown) меняют состояние S или правки → render()
```

Модель пересчитывается целиком при каждой отрисовке: 71 позиция, расчёт занимает единицы миллисекунд, кэширование не требуется.

## 3. Модули

### 3.1. Расчёт — `src/engine.js`
Экспорт: `build`, `agenda`, `sanitizeEdits`, `calendar`, `dn`, `fmt`, `iso`, `parseISO`, `todayLocal`, `plural`, `STATUSES`, `CLS`. Нет обращений к DOM, `window`, хранилищу; подключается в браузере как глобальный `Engine`, в Node.js — через `require`.

| Функция | Правила |
|---|---|
| `calendar(holidays)` | рабочие дни по производственному календарю РФ, интервал (a; b] со знаком (Р-04, Р-25, Р-65) |
| `build(...)` | отображаемый статус и наследование (Р-15); признаки срока, в том числе «срок прошёл, нет подтверждения» после даты отметок (Р-74); база 47 (Р-17, Р-21); показатели; периоды; окна пути (Р-47); «Требует внимания» (Р-26) |
| `sanitizeEdits(seed, raw)` | проверка отметок из хранилища: только позиции План-графика, статусы из перечня, ограниченные строки (Р-70) |
| `agenda(M)` | повестка в формате письма (Р-33, Р-50); разделы I–IV `sections` (раздел «подтвердить выполнение» — после даты отметок, Р-74); списки для формата «Для обсуждения» |

### 3.2. Интерфейс — `src/ui/`
Модули исполняются в одной области видимости внутри функции-обёртки; `tools/build.py` соединяет их в порядке `UI_PARTS`. Модуль вправе использовать только объявления из модулей выше по списку и функции, вызываемые после запуска.

| Порядок | Модуль | Содержание |
|---|---|---|
| 1 | `core.js` | данные, параметры ссылки, хранилище, состояние `S`, форматы, роли участников (Р-61), шкала этапа |
| 2 | `chrome.js` | шапка, плашки, панель инструментов, заголовок режима, подписи вех по дорожкам |
| 3 | `summary.js` | «Сводка» В1 и В3 |
| 4 | `gantt.js` | «График работ», мобильный список |
| 5 | `focus.js` | «Ближайшие сроки» |
| 6 | `board.js` | «Статусы» |
| 7 | `milestones.js` | «Вехи» |
| 8 | `panel.js` | карточка работы |
| 9 | `dialogs.js` | повестка оперативки, отметки в этом браузере (Р-71), справка |
| 10 | `main.js` | `render`, `syncUrl`, навигация, обработчики событий, запуск |

### 3.3. Конфигурация — `src/config.js`
`SHORT` (краткие наименования 71 позиции, Р-55), `CHAIN`/`FEEDER` (путь к демонстрации, Р-24), `HOLIDAYS` (Р-04, Р-65), `LINKS` (связанные работы), `ORGS` (Р-28), ключи хранилища.

### 3.4. Оформление — `src/style.css`
Все значения — токены из `TOKENS.md` (цвет, шрифт, шкала отступов, радиусы, тени); светлая и тёмная темы переопределяют только токены. Компонентные размеры (высота строк, ширины колонок, геометрия шкал) перечислены в `TOKENS.md` §6–7.

### 3.5. Шаблон и сборка — `src/template.html`, `tools/build.py`

| Выход | Состав |
|---|---|
| `versions/v1-panel.html`, `v2-registry.html`, `v3-path.html` | шаблон + стили + данные + конфигурация + расчёт + интерфейс; различаются `VARIANT` |
| `versions/index.html` | страница сравнения версий из `src/versions.html` |
| `index.html` | выбранная версия (В1, Р-55) |
| `dist/crm-ymg-iim-stage1-offline.html` | выбранная версия без Google Fonts — для внутреннего контура |

## 4. Состояние

| Слой | Где | Переживает перезагрузку | Передаётся ссылкой |
|---|---|---|---|
| Исходные данные | `window.SEED` | да (в файле) | — |
| Правки: статус, документ закрытия, комментарий | `localStorage`, ключ `CONFIG.STORAGE_KEY`; при загрузке — `sanitizeEdits` | да, в этом браузере | нет (Р-41, Р-70) |
| Тема | `localStorage` + `?theme` | да | да |
| Режим, открытая работа, отбор | `S` + адрес (`?view`, `?item`, `?who`, `?sec`, `?exec`) | да, через адрес | да (Р-66, Р-67) |
| Раскрытые разделы, выбранная дата, период, открытые окна | `S` | нет | нет |

Любой доступ к `localStorage` обёрнут в `try/catch`; без хранилища страница работает и сообщает об этом в подвале.

## 5. Расширение

- **Новая редакция План-графика**: заменить `data/seed_ymg_stage1.json` (та же схема), обновить `SHORT` для новых позиций, запустить `tools/check.sh`. Тест «краткие наименования у всех позиций» укажет пропуски; эталонные числа в `tests/engine.test.js` и `tests/behaviour.js` пересчитать по новой редакции.
- **Новый режим**: модуль `src/ui/<режим>.js` с функцией `view<Режим>()`, пункт в `VIEWS` (`core.js`), ветка в `render()` (`main.js`), имя в `UI_PARTS` (`build.py`), сценарий в `tests/behaviour.js`.
- **Общее хранение отметок (Р-41)**: заменить объект `store` в `core.js` на обращение к серверу с тем же интерфейсом `get/set`; расчёт и отображение не меняются.
- **Роли и участники (Р-61)**: функции `resp`, `cosOf`, `OWNER_F` в `core.js`.

## 6. Проверки

`bash tools/check.sh` (≈ 3 минуты; `SHOTS=0` — без снимков, `AXE=…/axe.min.js` — с аудитом доступности):

| Шаг | Средство | Что гарантирует |
|---|---|---|
| Данные | MD5 | исходные файлы не изменены |
| Сверка | `tools/reconcile.py` | JSON совпадает с `.xlsx` по составу и порядку позиций |
| Расчёт | `tests/engine.test.js` (16) | календарь, база 47, показатели, периоды, наследование, окна пути, повестка, правки, проверка отметок |
| Поведение | `tests/behaviour.js` (37) | сценарии в браузере, стресс-данные, ссылки, роли, сверка чисел между режимами, сборка без сети |
| Доступность | `tests/targets.js`, `tests/a11y.js`, `tools/contrast.py` | зоны нажатия ≥ 40 px, WCAG 2.2 AA, контраст |
| Язык | `tests/latin.js` | латиница только «CRM» и в данных |
| Вид | `tests/shots.js` | 28 снимков, консоль без ошибок |

Публикация: `bash tools/publish.sh` — копирует `index.html`, `versions/`, `dist/` и три снимка в ветку `gh-pages`.
