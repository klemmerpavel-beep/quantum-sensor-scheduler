# Совет по развилкам С-1…С-3 · этап 3

Состав: четыре независимых участника с разными методами — первые принципы, доказательная база, лучший контраргумент, практика. Три стадии: независимые мнения (параллельно), слепое взаимное рецензирование (ответы обезличены и перемешаны, свой ответ участник не оценивал), синтез председателя.
Исходные условия: `docs/DECISIONS.md` (Р-01…Р-43), `docs/DATA_MAP.md`, `data/seed_ymg_stage1.json`.

**Оговорка о независимости.** Участники — модели одного семейства. Разнообразие обеспечивалось методами, а не разными поставщиками, поэтому единодушие совета (С-1 и С-2) — слабое свидетельство правильности. Общие слепые зоны при такой схеме не выявляются.

## С-1. Ведущий экран

### Ответ
По умолчанию открывается «Сводка» (Р-08 подтверждается). При этом «Сводка» должна содержать ось времени и сравнение «закрыто» с планом на дату, а не с долей прошедшего срока. «Гант» — экран подтверждения: каждый элемент «Сводки» открывает «Гант» в заданном срезе. Версии продукта (Р-43) различаются композицией первого экрана, а не параметром `?view`.

### Обоснование
- Критерий «ответ за 10 секунд без прокрутки» (постановка, BRIEF.md раздел 2 и 5Г) «Гант» не выполняет. На 1440×900 видно около 25 из 71 строки, нужна легенда, на 390 px «Гант» заменяется списком (BRIEF.md, раздел 7).
- **Поправка к Р-21, принятая по рецензированию.** Сопоставление «закрыто 21 % при прошедших 33 % срока» — ложный базис: сроки позиций распределены по этапу неравномерно (две волны, DATA_MAP §5.1). Правильный базис — план на дату. На 28.09 в базе из 47 позиций срок наступил у 10: из них 8 закрыты, 2 просрочены (2.1.5, 2.1.7). Ещё 2 позиции закрыты досрочно (1.5, 2.1.8). Совпадение «10 = 10» — случайное равенство разных множеств, и вывод «проект идёт по плану» отвергнут. К 30.09 срок наступит у 18 позиций.
- Ось времени в «Сводке»: полоса этапа 13.08.2026–01.02.2027 с линией «Сегодня», вехами и недельной плотностью сроков. Это закрывает главный довод в пользу «Ганта» — узнаваемость и видимость концентрации сроков.
- Переходы «Сводка → Гант»:
  - плитка «Просрочено» → строки с этим признаком;
  - риск → строка позиции с подсветкой;
  - цепочка → срез «Цепочка ЛО» (9 строк на один экран);
  - веха → прокрутка к дате.

### Оси различия версий (для этапов 14–16)
| Версия | Первый экран | Для кого сильна |
|---|---|---|
| **В1 «Панель»** | «Сводка»: KPI в сравнении с планом на дату, полоса времени, прогресс разделов, «Топ-5», нитка цепочки | руководство, 10-секундный ответ |
| **В2 «Реестр»** | «Гант-реестр» с закреплённой полосой из 4–5 показателей сверху и развёрнутой цепочкой ЛО | аудитория, привыкшая к MS Project и подписанному ПГ |
| **В3 «Путь к ЛО»** | повествование по цепочке до демонстрации 30.11: звенья, окна, риски; KPI по краям | разговор о главном результате этапа |

Все версии используют один модуль расчёта и один свод правил (Р-43).

### Разногласия
- **Экран В2.** Двое участников предлагали версию с «Гантом» на первом экране, третий — «Сводку» вокруг ленты времени. Решено в пользу В2 «Реестр»: только он проверяет довод об узнаваемости, а лента времени уже вошла в В1. Выбор между версиями за заказчиком (Р-43).

### Уверенность
Около 80 %. Решение изменит прогон В1 и В2 на реальном экране совещания, если руководство в В1 будет спрашивать «откуда цифры».

## С-2. Отрисовка «Ганта»

### Ответ
DOM, семантическая таблица `<table>` с `table-layout: fixed`. Каждая строка содержит и реестр, и ячейку шкалы. Полосы позиционируются внутри ячейки через CSS-переменные (`left`/`width` в долях интервала этапа). Стрелки связей не рисуются. SVG не используется, кроме инлайн-иконок.

### Обоснование
- Одна строка таблицы содержит и реестр, и шкалу, поэтому высоты синхронизируются без JS. Схема «две колонки» или «SVG-сцена» требует синхронизации геометрии и пересчёта при сворачивании.
- Доступность без эмуляции:
  - табличная семантика;
  - `aria-expanded` у строк разделов;
  - фокус на строке;
  - полосы помечены `aria-hidden`, в ячейку шкалы положен скрытый текст «срок 15.09.2026, просрочено 13 дн.».
- Печать: `<thead>` повторяется на каждой странице; `print-color-adjust: exact` сохраняет штриховку; A3 альбомный лист.
- На 390 px та же разметка перестраивается в список-карточки: колонка шкалы скрывается. SVG потребовал бы второй реализации.
- Плотность одинакова в обоих подходах: около 860 px на 172 дня, то есть примерно 5 px на день, без горизонтальной прокрутки на 1440.
- Следующие итерации (роли, общее хранение, импорт .xlsx, второй проект) меняют слой данных, а не способ отрисовки; строка DOM естественно принимает встроенное редактирование.
- Элементы шкалы:

| Элемент | Способ |
|---|---|
| Статус | класс полосы |
| Производное начало | сегмент с пониженной непрозрачностью |
| Просроченная часть | `repeating-linear-gradient` |
| Веха | повёрнутый квадрат |
| Засечка контрольной даты | 2 px |
| Прогресс группы | внутренняя полоса |
| Линия «Сегодня» | общий абсолютный слой |

### Разногласия
- **SVG-накладка для соединителей цепочки.** Два участника предлагали её, один выступал против. Решено без стрелок. На двух плановых перекрытиях стрелки шли бы назад и читались бы как ошибка, а накладка создаёт второй источник координат. Цепочка выделяется обводкой полос звеньев, номерами звеньев и подписью окна у строки следующего звена.
- **Связи вне цепочки.** Шесть связей уровня EXTRACTED (DATA_MAP §8) показываются текстом в боковой панели («Приёмка — поз. 2.2.6»), а не линиями. Так соблюдается и Р-03.

### Уверенность
Около 85 %. Решение изменит обязательное требование рисовать зависимости линиями на следующих итерациях: тогда станет оправдан SVG-слой.

## С-3. Модель окна критической цепочки

### Ответ
У каждого звена два числа в рабочих днях: плановое окно и прогнозное окно. Цвет зависит от того, насколько прогноз хуже плана, а не от знака окна. Плановое перекрытие без сдвига исполнения нейтрально. В интерфейсе величина называется **«окно»**, а не «буфер»: это не буфер по методу критической цепочки.

### Формулы
Δ(a, b) — число рабочих дней в интервале (a; b] по календарю Р-04, со знаком. Конвенция проверена по данным: 15.09 → 30.09 = 11, 27.11 → 30.11 = 1.

- Плановое окно: **P_i = Δ(due_i, due_{i+1})**. Константы подписанного документа: 11, 32, −1, −5, 10, 5, 1; питающая — 41.
- Прогноз окончания, нижняя граница «не ранее»:
  **F_i = closed_date_i**, если звено закрыто;
  иначе **F_i = max(due_i, сегодня, F_{i−1} ⊕ min(P_{i−1}, 0))**, где ⊕ — сдвиг на рабочие дни.
  Сдвиг предыдущего звена переносится вниз по цепочке только сверх перекрытия, разрешённого самим План-графиком. Длительности и лаги не выдумываются.
- Собственный сдвиг звена: **s_i = Δ(due_i, F_i)** (≥ 0).
- Прогнозное окно: **R_i = Δ(F_i, due_{i+1})**.
- Израсходовано: **E_i = P_i − R_i**.

### Состояния окна
| Состояние | Условие | Отображение |
|---|---|---|
| В плане | E = 0, P ≥ 0 | нейтрально; при P ≤ 1 пометка «тонкое окно» (2.2.5.3 → 2.2.5.5) |
| Перекрытие по ПГ | E = 0, P < 0 | нейтральная штриховая скобка, подпись «−5 раб. дн. · заложено в План-графике» |
| Окно расходуется | E > 0, R ≥ min(P, 0) | оранжевый; подпись «осталось R из P раб. дн.; срыв с ДД.ММ.ГГГГ» |
| Срыв | R < min(P, 0) | красный; подпись «срыв N раб. дн.» |
| Исполнено | оба звена закрыты | факт без окраски |

- Цвет цепочки в целом — худшее из состояний окон.
- Просрочка звена (Р-19) — отдельный признак узла: окно описывает связь между звеньями, просрочка — само звено.
- Дата срыва — первый рабочий день после due_{i+1}.

### Проверка на 28.09.2026
- Звено 2.1.7 красное: «просрочено 13 дн.».
- Окно 2.1.7 → 2.1.6 оранжевое: «осталось 2 из 11 раб. дн.; срыв с 01.10.2026».
- Остальные окна не изменились. Два плановых перекрытия (2.2.2 → 2.2.5.1: −1; 2.2.5.1 → 2.2.4.1: −5) нейтральны с подписью.
- Цепочка в целом оранжевая.
- Если 2.1.7 не закроют к 01.10, окно станет −1 и красным, цепочка — красной.

### Отображение
- «Сводка»: нитка из восьми звеньев и питающей 2.1.9, между звеньями подписи «11 → 2 раб. дн.», «−5 по ПГ».
- «Гант»: скобка от срока предыдущего звена до срока следующего на строке следующего звена. Для перекрытия скобка обращена назад и заштрихована серым.
- Единицы подписываются всегда (Р-25).

### Отвергнуто
- Буфер по методу критической цепочки (fever chart, root-sum-square) — нет длительностей.
- Окраска по знаку планового окна — цепочка горела бы всегда, и сигнал терял бы смысл.
- Пороги в процентах израсходованного окна — ложная точность на окнах в 1–11 дней.
- Прогноз «срок + дни просрочки» — экстраполяция темпа без основания.
- Календарные дни — противоречат Р-25.

### Разногласия
- **Распространение сдвига.** Один участник отвергал перенос сдвига вниз по цепочке, как требующий выдуманных лагов. Рецензент показал, что лаг min(P, 0) взят из подписанного документа, и без переноса сдвиг звена не доходит до окон ниже по цепочке. Принято распространение с пометкой «не ранее».
- **Оранжевая цепочка при красном звене.** Может ли это восприниматься как смягчение, остаётся открытым риском (см. ниже).

### Уверенность
Около 75 %. Решение изменят два свидетельства:
1. Заказчик на прогоне сочтёт «оранжевая цепочка при красном звене» противоречием. Тогда цепочка краснеет при просрочке любого звена.
2. Заказчик подтвердит, что перекрытие 2.2.2 / 2.2.5.1 / 2.2.4.1 — ошибка сроков в ПГ, а не заложенная параллельность. Тогда плановые отрицательные окна должны быть красными с первого дня.
