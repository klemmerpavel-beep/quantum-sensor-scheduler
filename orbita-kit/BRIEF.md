# Бриф: онлайн-планер статуса реализации проекта (рабочее имя «Орбита»)

**Пилотный проект:** ОКР «ЯМГ-ИИМ», этап 1 (Договор № 868/2666-Д от 13.08.2026; этап 1 — 13.08.2026 – 30.12.2026)
**Заказчик брифа:** П.С. Клеммер, руководитель направления «Квантовые сенсоры», ООО «СП «Квант»
**Дата:** 28.09.2026 · **Стадия:** презентационный прототип (визуальный образ), без бэкенда

---

## 1. Идея

Онлайн-страница, отображающая статус реализации проекта по позициям План-графика. Одна ссылка — для исполнителей (что и когда сдавать) и для руководства (где проект, что горит, что закрыто). План-график в Excel остаётся первичным документом; страница — его живое отображение.

Цель текущей итерации — **одна ведущая картинка**, пригодная для показа руководству. Функционал (роли, общий доступ к отметкам, комментарии, интеграции) докручивается следующими итерациями.

## 2. Проблема, которую решаем

| Сейчас | После |
|---|---|
| План-график и вкладка «Важное» ведутся параллельно и расходятся (нумерация, даты) | Горизонты «срочно / 1 месяц / 2 месяца» вычисляются из реестра автоматически |
| Статус — в письмах и протоколах оперативок | Статус позиции виден на странице по ссылке |
| Просрочки выявляются при подготовке повестки вручную | Просрочки подсвечиваются в момент наступления даты |
| Руководство получает статус через пересказ | Руководство открывает ссылку и видит сводку за 10 секунд |

## 4. Исходные данные

Источник — книга План-графика этапа 1: вкладка «План-график (На подписание)» (71 позиция) и вкладка «Важное» (отметки о выполнении и горизонты). Данные перенесены в `data/seed_ymg_stage1.json` без изменения наименований, сроков и нумерации.

**Словарь статусов** (приведён из отметок вкладки «Важное»): Не начато · Нет отметки · В работе · Подготовка материалов · Ожидаем документ · На согласовании · Закрыто. «Нет отметки» — срок наступил, отметки во «Важном» нет (6 подпозиций 2.1.1 и 2.1.2). Производные признаки вычисляются, не вводятся: *Просрочено*, *Срок ≤ 7 дней*.

**Срез на 28.09.2026:** закрыто 10 позиций; в работе/ожидании 7 (1.4, 2.1.1, 2.1.2, 2.1.5, 2.1.6, 2.1.7, 2.1.9); 9 позиций со сроком 30.09.2026.

**Цветовая семантика** — совпадает с вкладкой «Важное»: зелёный — закрыто; оранжевый — срочно, требует действия; светло-зелёный — идёт по графику; красный — просрочено; нейтральный серый — будущие позиции.

**Критическая цепочка лабораторного образца** (предложение, подтвердить): 2.1.7 → 2.1.6 → 2.2.2 → 2.2.4.1 → 2.2.5.1 → 2.2.5.2 → 2.2.5.3 → 2.2.5.5, со связью от 2.1.9 (ПМИ).

## 5. Варианты основного отображения

Прототип содержит **пять режимов**, переключаемых сегментированным контролом в шапке. Для презентации выбирается ведущий (рекомендация — вариант А).

### Вариант А. «Гант-реестр» (рекомендуемый ведущий экран)
Слева — иерархическая таблица (№, наименование, ответственный, срок, статус), справа — временная шкала 13.08.2026–01.02.2027 с разбивкой по неделям. Полосы позиций окрашены по статусу; вехи — ромбы (демонстрация ЛО 30.11, передача ТП 01.12, окончание этапа 30.12, акт сдачи-приёмки 01.02.2027). Вертикальная линия «Сегодня». Разделы сворачиваются. Просроченная часть полосы — штриховка.
*Сильная сторона:* привычен руководству, показывает загрузку во времени и концентрацию сроков в конце сентября.
*Референсы:* Linear Timeline, GitHub Projects Roadmap, TeamGantt, MS Project (как привычная для аудитории база).

### Вариант Б. «Доска статусов» (плашки / канбан)
Колонки по словарю статусов, в каждой — карточки позиций: номер, наименование в две строки, ответственный (бейдж организации), срок с индикатором остатка дней. Фильтр по ответственному и разделу.
*Сильная сторона:* наглядно показывает, где «застряло» (например, пять позиций в колонке «Формируется ответ» у Исполнителя).
*Референсы:* Linear Board, Jira Board, Height.

### Вариант В. «Фокус периода» (горизонты)
Три полосы-горизонта, вычисляемые от текущей даты: **Просрочено** · **Ближайшие 14 дней** · **30 дней** · **60 дней** + свёрнутый блок **Закрыто**. Повторяет логику вкладки «Важное», но без ручного ведения.
*Сильная сторона:* рабочий экран руководителя перед оперативкой; готовая основа повестки.
*Референсы:* Things 3 (Today/Upcoming), Linear My Issues.

### Вариант Г. «Панель руководства» (executive summary)
Верхний ряд KPI-плиток: % закрытых позиций (по числу и по весу), просрочено, в работе, дней до окончания этапа, дней до демонстрации ЛО. Ниже — полоса прогресса по разделам 1 / 2.1 / 2.2 / 3, лента ключевых вех и блок «Топ-5 рисков» (просроченные позиции критической цепочки).
*Сильная сторона:* экран для ссылки руководству — ответ на вопрос «как дела» без чтения таблицы.
*Референсы:* Vercel Dashboard, Stripe Dashboard, Linear Projects overview.

### Вариант Д. «Хронология вех» (milestone timeline)
Горизонтальная лента этапа с ключевыми вехами и вертикальными «гроздьями» позиций под каждой датой; ширина грозди — количество позиций. Визуализирует пиковую нагрузку (9 позиций со сроком 30.09, 10 — на 27.11).
*Сильная сторона:* аргумент в переговорах с Исполнителем о концентрации сроков.

## 6. Уникальные функции, привязанные к специфике ОКР

1. **Вычисляемый «Фокус периода».** Горизонты не ведутся руками — расхождение План-графика и оперативного листа исключается конструктивно.
2. **Критическая цепочка лабораторного образца.** Отдельная подсветка последовательности: план закупок МТР (2.1.7) → договоры с соисполнителями (2.1.6) → работы ИХС (2.2.2) → КД на ячейку (2.2.4.1) → макеты ячеек и эксперименты (2.2.5.1) → сборка ЛО (2.2.5.2) → испытания (2.2.5.3) → демонстрация 30.11 (2.2.5.5). Для каждого звена — **буфер в днях** до следующего; при отрицательном буфере цепочка краснеет.
3. **Две даты у позиции.** Срок по План-графику (неизменяемый) и контрольная дата по протоколу оперативки. На Ганте контрольная дата — тонкая засечка; сдвиг виден без изменения подписанного документа.
4. **«Закрыто» только с реквизитом.** Перевод в «Закрыто» требует указать выдаваемый документ (№ письма / дату / наименование). Статус «взято в работу» не принимается — повторяет требование «только факты» из повесток.
5. **«Что изменилось с прошлой оперативки».** Переключатель даты сравнения; изменённые позиции подсвечиваются, сводка — счётчиком в шапке.
6. **Генерация повестки.** Кнопка «Повестка оперативки» собирает просроченные и позиции 14-дневного горизонта в текст формата «Наименование — комментарий (п. 2.1.4)», пригодный для письма Исполнителю.
7. **Окно приёмки в рабочих днях.** Для позиций приёмки (2.2.6, 2.2.7, 3.9–3.11) — расчёт по производственному календарю РФ с предупреждением, если окно меньше нормативного (пример: 12 рабочих дней при отведённых 10).
8. **Режим «Для руководства».** Параметр ссылки `?view=exec` открывает панель Г без элементов редактирования.
9. **Экспорт в формат План-графика.** Обратная выгрузка в .xlsx с сохранением нумерации и колонок (этап 2 функционала).

## 7. Визуальная айдентика и UX

- **Характер:** инженерная панель — плотная, спокойная, без декора. Ориентир — Linear / Vercel, а не корпоративный портал. Акцент на содержании позиций.
- **Название на странице:** «Орбита · ЯМГ-ИИМ · Этап 1». Логотипы и фирменный стиль Госкорпорации «Росатом» не используются.
- **Палитра:** графитовая нейтральная шкала + один акцент (кобальт) + семантические цвета статусов (п. 4). Тёмная и светлая темы.
- **Типографика:** Inter или IBM Plex Sans (кириллица), табличные цифры для дат и номеров; IBM Plex Mono — для номеров позиций.
- **Плотность:** строка реестра 36 px, шрифт 13–14 px; на экране 1440×900 — не менее 25 позиций без прокрутки.
- **Даты:** ДД.ММ.ГГГГ, остаток — «через 5 дн.» / «просрочено 3 дн.».
- **Адаптивность:** телефон — режимы В и Г (Гант скрывается, заменяется списком).
- **Доступность:** статус не передаётся только цветом — дублируется иконкой/текстом.

## 8. Объём текущей итерации

**Входит:** один самодостаточный `index.html` (без сборки), пять режимов, переключение, фильтры по ответственному и разделу, поиск по номеру/наименованию, отметка выполнения и комментарий локально (в памяти страницы), тёмная/светлая тема, данные План-графика этапа 1 (71 позиция).

**Не входит:** авторизация, общий доступ к отметкам между пользователями, загрузка файлов, импорт .xlsx, уведомления, интеграции. Это этапы 2–4.

## 9. Этапы развития

| Этап | Содержание |
|---|---|
| 1 | Презентационный прототип (этот бриф) |
| 2 | Публикация по ссылке с общим хранилищем отметок и комментариев; режим только чтения для руководства |
| 3 | Импорт .xlsx План-графика, журнал изменений с автором, роли (руководитель / исполнитель / наблюдатель) |
| 4 | Второй проект («Гроза»), переключение проектов плашками, экспорт в .xlsx, уведомления |

## 10. Критерии приёмки прототипа

1. Открывается локально двойным щелчком и как опубликованная страница, без ошибок в консоли.
2. Все пять режимов работают на одном наборе данных; переключение без перезагрузки.
3. Отметка «Закрыто» мгновенно отражается во всех режимах и KPI.
4. Линия «Сегодня» и признак «Просрочено» вычисляются от текущей даты (для демонстрации — параметр `?today=2026-09-28`).
5. Корректное отображение на 1440 px и 390 px, в светлой и тёмной теме.
6. Ни одного англоязычного элемента интерфейса.
